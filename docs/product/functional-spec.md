# 功能与交互规格

- 更新日期：2026-10-06
- 状态：已确认的产品行为与本轮开发验收基线；小程序实现及用例验收待完成。
- 产品范围与需求编号见 [PRD](prd.md)，领域概念见 [GLOSSARY](../../GLOSSARY.md)。

本文描述每项功能的入口、操作、结果和异常行为。开发某项功能时，先阅读对应章节，再核对第 9 节的验收用例。布局与视觉表现见[页面设计](../design/README.md)；数据结构、接口及恢复机制见[技术设计](../technical/design.md)。维护分工见[文档入口](../README.md#文档维护)。

## 1. 本轮交付与范围

本轮完成可操作、可保存数据、前后端可联调的小程序核心功能。第一条实现链路为“导入菜单 → 查看结果与详情 → 在 AI 对话中获得模拟推荐与算价回复 → 重新打开历史”，随后补齐 PRD 的首版其余功能。

本轮完成条件：

- 主要操作能产生对应的页面状态与业务结果。
- 偏好、个人沟通卡、记录及其文字和图片能实际保存、读取与删除。
- 前后端核心流程能处理约定的请求、状态、错误和恢复场景。
- 固定模拟结果覆盖成功、部分成功和失败；五种静态界面语言及旧动态内容的混合展示通过页面检查。

真实 AI、模型选择、回复策略与 Prompt 留待后续阶段。当前只实现调用边界、模拟结果展示和相关状态流转；模拟通过不代表真实识别、翻译、对话质量或性能通过。

首版范围边界：菜品卡片用于浏览和查看详情，推荐与算价在对话中完成。首版没有独立选菜状态、数量编辑、购物车、点餐清单、餐厅下单或支付。识别菜名保持原结果，用户可核对原图、补图或在对话中补充；不建设菜名编辑入口、覆盖字段和保存接口。个人沟通卡编辑与饮食偏好修改仍属于首版。

## 2. 首次使用、导航与语言

依据：PRD 4.1、4.4、F1、A22–A25。

### 2.1 首次进入与主导航

首次进入时根据系统语言匹配英语、日语、韩语、西班牙语或简体中文。匹配成功直接进入拍照首页，在页内提供简短引导和可跳过的偏好邀请；未匹配时先选择语言，再进入首页。始终保留明显的语言切换入口，用户无需操作登录页面即可开始核心流程。

| 底部入口 | 可访问内容 |
| --- | --- |
| 拍照 | 拍摄、相册导入、最近记录及其处理状态 |
| 沟通卡 | 个人卡片的浏览、管理、展示与文字沟通 |
| 我的 | 历史记录、语言设置与饮食偏好 |

结果、菜品详情与独立 AI 对话页从相关记录进入。返回遵循实际进入路径，并恢复来源页面的浏览位置；语言与偏好设置也返回发起入口。完整导航与逐页布局见[核心页面规划](../design/pages.md#navigation)，页面中文名称对应五语言静态文案。

### 2.2 语言切换与内容保留

| 内容 | 切换语言后的行为 |
| --- | --- |
| 按钮、导航、标题、表单、引导、加载和错误提示 | 直接切换为内置的对应语言文案 |
| 已内置多语言版本的预置沟通卡文案 | 随界面语言切换；用户已编辑的内容按下一行处理 |
| 已有译图、菜品解释、聊天、推荐、算价回复，以及已编辑／自定义／AI 生成的个人卡片 | 保留原内容与原语言 |

切换操作只更新静态资源，不调用 AI、不重新生成或清空已有内容，也不要求为离线回看补做翻译。原始中文菜名始终可见或可直接查看。新 AI 请求如何选择回复语言在后续 Prompt 阶段确定；本轮使用模拟场景指定的语言。

页面检查覆盖五种语言下导航、按钮、标题、表单和状态提示的宽度、换行、对齐、遮挡与截断，同时覆盖静态界面与旧动态内容语言不同的情况。

## 3. 图片输入与提交

依据：PRD F2、A3、A15、A25、A27–A29。

### 3.1 输入入口与记录归属

相机与相册均为正式输入方式。进入拍照页先显示操作入口，用户点击拍摄后才打开相机，也可先确认语言或直接导入截图；相机不可用时说明原因并保留相册入口。首屏与最近记录布局见[拍照首页设计](../design/pages.md#entry)。

拍摄或导入前选择“菜单／菜品”模式，默认菜单；追加照片时也可选择。实际菜品照片优先引导拍摄一道菜。模式表达输入用途，不改变记录归属：

| 发起入口 | 确认提交后的结果 |
| --- | --- |
| 拍照页直接拍摄或导入 | 新建一条记录；旧记录及其菜单、图片和对话保持独立 |
| 已有结果页的“添加照片” | 补充当前记录；保留原有图片、卡片和对话 |

用户无需在拍照前单独建立“本次用餐”。最近记录与历史都可以进入原结果页，再继续追加图片。

### 3.2 提交前预览

菜单图片支持相册多选。提交前明确当前是新建还是追加，允许查看大图、移除和排序；确认后按剩余图片及其顺序统一提交。空批次不能提交，取消或退出预览不发起处理并返回发起入口；关闭预览大图保留本批选择、顺序与位置。列表和控件见[提交前预览设计](../design/pages.md#preview)。

纸质菜单照片、普通电子菜单截图、长截图和同一菜单的多张补充图片均为正式输入。长截图需覆盖上传、处理、图片缩放和卡片浏览全流程。图片数量、大小及格式边界随技术验证确定，不在本规格预设数值。

### 3.3 上传、处理与失败

确认提交后进入对应记录的结果页，每张图片分别呈现待上传、上传中及后续阶段的排队、处理中、成功或失败状态。本批图片全部上传完成且后端已接收处理后，才显示可离开或退出、稍后回看的说明。卡片与译图分别展示可用结果，某图或某阶段失败不清空其他成功内容；重试针对失败图片或阶段。

未上传成功的材料保留在本机，重新进入后仍能找到。网络恢复后由用户点击重试，不自动提交。图片已上传且开始处理后的离开、退出和恢复行为见第 8.3 节；结果保存状态见第 8.1 节。

## 4. 结果浏览与菜品详情

依据：PRD F3、F10、A2、A4、A8、A16、A24、A26、A33。

### 4.1 图片与卡片浏览

同次菜单识别自动提供图片视图和结构化菜品卡片，无需进入聊天或点击推荐。结果页提供原图／译图切换、添加照片及固定的“问 AI”入口；分区与线框见[结果页结构](../design/pages.md#images)。

缩略图选择当前图片，下方筛选展示与该图关联的菜品卡片。切换图片或原图／译图只改变展示范围，保留其他卡片和记录内容；AI 对话仍使用同一记录的全部相关菜单与图片。一个菜品可以关联多张图片，界面筛选不决定重复菜品与规格的合并规则；该规则继续按 PRD R2 验证。

首次查看某张图片时优先显示已经完成的译图，译图尚未可用或无须生成时显示原图。后台译图完成只更新其可用状态，不突然切换正在查看的原图。每张图片分别保存手动原图／译图选择，换图、往返页面和恢复记录时沿用已有选择。

点击图片可全屏核对、缩放、滚动长图，或切换图片及原图／译图。全屏与结果页共用当前图片及每图原译选择，关闭后恢复来源视图的浏览位置；具体布局见[全屏图片设计](../design/pages.md#fullscreen)。原图、译图与卡片的菜名、价格和来源对应。

| 结果状态 | 可见内容与反馈 |
| --- | --- |
| 卡片先完成、译图仍在处理或失败 | 已完成卡片可读，译图显示其真实状态，失败项可重试 |
| 当前图片没有卡片 | 说明原因，不使用其他图片的卡片填充 |
| 本次目标语言为简体中文 | 保留中文图片展示，照常生成解释卡片 |
| 实际菜品照片没有可翻译文字 | 显示原图与解释，无须生成重复译图；无须译图不作为错误 |
| 菜品身份无法确定 | 保留不确定性，允许补充说明或更清晰的图片，不强行对应菜单菜品 |

### 4.2 菜品内容与详情

卡片优先展示原始中文菜名、该内容生成时目标语言的菜名、可识别价格和一句话解释。详情进一步展示主要食材、口味、常见做法、可能的过敏原或饮食冲突、吃法、简短饮食文化及待确认事项，并保留原图核对入口。

未知价格明确标为未知，不依据菜品知识生成价格。根据菜名推断的食材与做法使用“常见做法”“可能包含”等表述，与本店已确认信息区分。电子菜单的导航、购物车、促销等非菜品内容不作为菜品推荐。

饮食提示的检查状态独立于菜品解释是否已存在，修改偏好后的行为见第 6 节。当前 AI 内容用固定样例展示，真实解释与图片翻译质量在实际接入后验收。

## 5. AI 对话与快捷建议

依据：PRD F5、F6、F11、A5、A17、A32。

### 5.1 进入、发送与结果

从结果页进入当前记录的独立聊天页，返回后继续浏览同一记录。用户可直接输入问题，或点击输入框上方的快捷建议；点击建议会生成当前语言的自然提问并发送，聊天中显示实际发送的文字。菜单场景可提供推荐、解释、算价和询问店员等建议，菜品照片场景可提供吃法、食材和菜品介绍等建议。

请求关联当前记录的菜单、照片、对话与个人偏好，不混入其他记录的餐厅菜品。回复可包含可进入详情的菜品引用或可收藏的沟通卡；收藏行为见第 7 节。

本轮使用固定回复验证发送、等待、展示与保存。真实推荐只从当前菜单中产生，明确冲突项不进入推荐，未知信息和待确认事项继续保留；用户可以在对话中表达想点的菜品和数量，参考金额作为回复保存。具体候选要求沿用 PRD F6，真实算价规则沿用 F11。

### 5.2 回复状态与重试

对话呈现草稿、已发送、等待、部分回复、完成、失败和重试中等状态。已接收的消息在离开页面或退出小程序后继续处理，重新进入后恢复原消息及回复状态。

失败时保留已显示片段并标记未完成；重试关联原问题，成功后替换对应未完成回复，不重复插入用户问题或拼接两次回答。重试过程中旧片段可以保留并标明状态；迟到的旧尝试不能覆盖当前回复。

本轮按技术设计每条记录同时处理一条用户请求，回复期间可编辑草稿，草稿不自动发送。未发送草稿按记录自动保存到本机，暂离或退出后继续编辑；发送或主动清空后移除对应草稿。每条记录分别恢复聊天阅读位置：停留在旧内容时，新回复提供查看入口，不强制滚动到底部；原本处于底部时接续最新回复。消息布局与输入区见[聊天页面规划](../design/pages.md#chat)，更细的输入禁用和停止操作随状态稿核对。

### 5.3 后续 AI 阶段的边界

规格、数量或价格不明确时如何追问，如何展示部分报价、调整连续对话中的算价，以及新请求如何选择回复语言，留待 AI 设计与 Prompt 阶段。本轮模拟不表示上述策略已确认；PRD 中价格未知不能编造等既有约束继续有效。

## 6. 饮食偏好与提示更新

依据：PRD F4、A6、A7、A20。

用户可跳过首次偏好设置、保存或随时修改偏好。过敏信息、饮食限制和口味偏好在同一页分组填写，各自允许文字补充，统一保存后生效；尚未保存的表单编辑不更新当前偏好。具体过敏原选项及宗教饮食要求的细分方式在内容准备阶段核验。未设置偏好时仍能使用核心流程，通用推荐说明尚未结合个人饮食限制。

明确冲突的菜品保留在菜单浏览结果中并显示原因，但不进入推荐；可能冲突或信息不足时标出原因，并提供向店员询问的入口。未识别到过敏原不等于可以放心食用，菜名、照片和常见菜谱也不能证明餐厅的宗教饮食资质或制作条件。详情与后续对话继续保留待确认事项。

修改偏好后，相关提示重新检查：

| 状态 | 行为 |
| --- | --- |
| 等待或检查中 | 明确标记尚未按新偏好完成检查 |
| 检查完成 | 应用与当前偏好对应的新提示 |
| 检查失败 | 显示失败，并保留“仍待按新偏好检查”的提示，不把旧提示当新结果 |

旧对话保留原文，基于旧偏好的推荐标记为需要重新确认，后续推荐使用新偏好。已接收任务使用提交时的输入快照，旧版本检查不得覆盖当前状态；版本处理见技术设计。

## 7. 个人沟通卡与双向文字翻译

依据：PRD F8、A9、A10、A31。

个人沟通卡独立于菜单记录：没有记录时也能使用预置卡片、创建自定义卡片和双向文字翻译，这些操作不创建记录。语言切换遵循第 2.2 节，本机保存与失败反馈遵循第 8.1 节；卡面、手势、控件和表单初值见[沟通卡与文字交流设计](../design/communication-cards.md)。

### 7.1 卡库与排序

卡片支持标题、分类、颜色、编辑、删除和手动排序，预置卡片同样可调整。卡库按“全部／饮食需求／餐桌沟通”筛选，预置、自建与收藏卡片混合归类。

所有卡片共享一套全局顺序，分类内排序只调整该类卡片已经占据的位置，其他类别的位置不变。例如全局顺序为“少辣／要水／询问配料”，把饮食需求中的“询问配料”移到“少辣”前，结果为“询问配料／要水／少辣”。顺序自动保存到本机；保存失败明确反馈并可重试，退出重进读取最后成功保存的顺序。

新建与收藏卡片放到全局顺序最前，原有卡片保持相对顺序。编辑已有卡片不改变顺序，包括修改分类。查看或展示也不改序；收拢后显示当前分类第一张卡。

只有首次使用默认收拢。暂离或退出重进恢复上次分类、收展状态和浏览位置；主动切换分类保留收展状态，从新分类第一张开始浏览。手势和首次操作提示按页面设计实现。

### 7.2 创建、编辑、收藏与草稿

用户输入想说的话，生成中文对照后可检查、编辑并保存；本轮生成使用模拟结果。卡片保留自身语言及中文对照，中文卡片避免重复相同文字。涉及具体菜品时保留中文菜名，复用时仍可辨认询问对象。

创建或编辑期间自动保留本机草稿，暂离或退出后可继续；正式卡片保持上次保存的内容，主动保存成功才创建或更新卡片，并清理对应草稿。保存失败保留草稿并反馈，不能显示为已保存。用户可放弃草稿；修改或放弃后，旧翻译不得覆盖新文字、恢复已放弃内容或自行创建卡片，版本机制见[技术设计](../technical/design.md#communication)。

对话中的沟通卡可收藏为包含完整文字与原语言的独立副本，不依赖来源记录存续。创建保存后返回卡库并显示新卡；编辑保存按原顺序返回卡库；从对话收藏后留在原对话并提示成功。

### 7.3 双向文字交流

游客与店员均可输入文字并获得对应翻译。当前交流保留双方最近各一组原文与译文，以及各自未发送草稿；切换说话者保留双方内容和状态。生成中、失败与离线状态明确可辨，等待新结果时仍可核对已有内容。

当前交流在本机保存，暂离及退出重进均恢复；主动“清空本次交流”才重置，不建立过去交流的历史列表。清空使原请求失效，迟到结果不得恢复已清空内容。新结果替换、失败反馈与清空的状态呈现见页面设计；语音输入、朗读和实时语音翻译留待后续。

## 8. 保存、离线、恢复与删除

依据：PRD F9、A12、A18、A19、A21、A29–A31；保存边界见 [ADR 0001](../adr/0001-local-history-temporary-processing.md)。

### 8.1 自动保存与容量不足

语言、偏好、个人卡片及完整历史以本机保存为准。记录及其文字、图片和对话随内容产生持续保存，处理完成的图片自动保存离线副本；本机历史默认不过期。

页面区分保存中、保存成功和保存失败，处理成功不等于已经可离线查看。本机写入失败时明确提示；空间不足时由用户选择清理，清理后可重试保存，不静默淘汰其他历史，也不把失败内容标成保存成功。

### 8.2 历史与离线回看

历史按记录创建时间倒序，分别呈现处理与本机保存状态。用户可重新进入对应结果，返回时恢复列表位置；记录信息与管理入口见[历史页面设计](../design/pages.md#history)。已成功保存的菜品文字、原图与译图、对话和沟通卡可离线查看；尚未保存的图片明确标出不可离线使用，需要新生成内容的操作等待联网。

本机历史的读取不依赖后端临时材料仍然存在。后端材料过期后，已保存内容仍可回看；用户主动发起新处理时，按技术设计准备新的临时上下文，保留本机记录。必要材料缺失时提示补图。首版不承诺跨设备恢复，清除本机数据后不承诺找回。

### 8.3 离开页面与退出恢复

图片已上传完成并开始处理后，在小程序内切换页面或退出都不停止处理。最近记录与历史能找到原记录，重新进入时恢复当时进度或结果，失败时可重试；重进页面不重复创建记录或发起同一处理。

未上传材料按第 3.3 节手动重试，聊天按第 5.2 节恢复。后端仅临时保留任务、输入与结果，正式保留期限仍待确定；恢复承诺需与技术设计中的到期状态一致。

### 8.4 删除与清空

用户可单条删除或清空历史。删除移除记录及关联图片、识别内容与对话，个人卡库中已收藏的独立副本继续保留。

处理中记录也可删除，删除后立即从历史隐藏，停止可停止的后续工作。上传完成、处理成功等迟到响应不能使其重新出现。离线删除保留必要的后端清理信息，联网后继续清理；本机删除完成不代表第三方服务已完成删除，第三方留存边界继续按 PRD R6 核实。

D17 补充检查：

- 对预置、自建与收藏卡分别验证第 7.1 节的分类、全局／分类排序、新增置前、编辑与展示不改序，以及保存失败与退出恢复。

- 按第 7.3 节验证双方结果、未发送草稿、说话者切换和退出恢复；清空后重进为空，注入迟到结果也不恢复旧交流。
