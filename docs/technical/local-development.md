# 本地 HTTP 联调

本轮已实现原生页面、本机文字与图片保存、真实上传、持久任务、重试、恢复、保存回执、删除和到期重建。生成内容由固定模拟适配器提供。HTTP 结构见 [OpenAPI](openapi.json)，行为与已执行证据见[核心实现验证](validation/2026-10-06-core.md)。

## 启动和连接

使用 Node.js 26 或更高版本，在仓库根目录执行：

```sh
npm ci
npm run server:dev
```

默认监听 `127.0.0.1:8787`，首行输出实际 URL。SQLite 元数据、原图和译图保存在项目外的 `~/.seefood/development`；使用 `SEEFOOD_DATA_DIR` 指定独立联调目录。Ctrl+C 停止服务，再以同一目录启动可恢复已接收任务及其身份。

`server:dev` 显式开启两个开发身份 `demo-owner-a`、`demo-owner-b`。服务生成随机业务令牌，只保存令牌散列；每个资源仍校验所有者。`npm run server` 默认关闭开发身份入口，`NODE_ENV=production` 始终关闭该入口。正式微信凭证交换尚未接入。

小程序的 `miniprogram/config/backend.js` 默认使用上述地址和 `demo-owner-a`。只有微信 `envVersion=develop` 才读取此开发配置；体验版、正式版及环境无法确认时关闭该适配器。微信开发者工具访问 localhost 需在本地项目设置中关闭合法域名校验，配置保存在不提交的 `project.private.config.json`。手机上的 `127.0.0.1` 指向手机自身，真机联调需另行准备可访问的服务与身份配置。

## 操作路径

1. 从拍照首页选择菜单／菜品模式，拍摄或导入真实图片；在预览中排序、移除和确认。本机原图与记录先保存，再按图上传并提交卡片、译图两个独立任务。结果页添加图片会追加到原记录；首页确认创建新记录。
2. 在结果页查看逐图进度、菜品详情和原图／译图。成功项先展示，失败项保留原输入；用户明确重试该项。译图独立下载、保存，保存失败可只重存文件或内容。已保存偏好时，主动图片处理产生的新菜品会发起偏好检查；重新进入页面和切换语言只恢复已有工作。
3. 进入记录聊天，发送快捷问题或输入文字。固定回复覆盖解释、推荐、参考算价和沟通卡；部分回复与重试使用同一消息对。发送期间可继续编辑草稿，回复到达时保留原阅读位置。沟通卡可独立收藏、创建、编辑、展示和排序；双向文字交流保留双方各自内容。
4. 重开历史从本机读取文字和实际文件；已接收但未完成的任务通过 GET 恢复。未上传材料、失败任务和未确认接收的提交均提供显式继续／重试入口。后端停服时仍可阅读已保存内容；本机缺图或写失败会显示对应恢复入口。
5. 删除或清空历史先持久保存删除标记，再清理本机文件及相关临时上下文；独立收藏继续保留。保存回执只在内容实际展示后确认展示版本，并分别记录本机结构和图片保存情况。临时材料过期不删除本机历史；下次主动发送、追加或重试按现存材料重建上下文，缺少必要原图时引导补图。

上述流程使用真实文件传输、SQLite 和本机存储。`tests/fixtures/` 提供单图、普通截图和长图材料，适合重复联调；它们只用于验证输入与交付，不代表真实识别质量。

## 运行配置

环境变量由 `server/start.ts` 读取；修改后重启服务。保留期限只影响新建上下文，既有上下文沿用持久保存的到期时间。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `SEEFOOD_DATA_DIR` | `~/.seefood/development` | SQLite、原图和译图目录，必须在项目外 |
| `HOST` / `PORT` | `127.0.0.1` / `8787` | 监听地址与端口；`PORT=0` 自动选空闲端口 |
| `SEEFOOD_DEV_IDENTITY` | 关闭 | 值为 `1` 时启用开发身份；生产环境仍关闭 |
| `SEEFOOD_DEV_IDENTITIES` | `demo-owner-a,demo-owner-b` | 开发身份白名单，逗号分隔 |
| `SEEFOOD_MOCK_SCENARIO` | 正常样例 | 选择下表中的固定生成情景 |
| `SEEFOOD_WORKER_DELAY_MS` | `20` | 执行器扫描间隔，最低 10 毫秒；便于观察接收与重启 |
| `SEEFOOD_TRANSLATION_DELAY_MS` | `0` | 固定译图生成等待时间，毫秒 |
| `SEEFOOD_CHAT_PARTIAL_DELAY_MS` | `350` | 半段聊天片段发布后到失败的等待时间，毫秒 |
| `SEEFOOD_JOB_PAGE_SIZE` | `50` | 上下文任务查询每页条数，最大 100；客户端跟随 `nextCursor` |
| `SEEFOOD_CONTEXT_RETENTION_MS` | `86400000` | 新上下文的硬到期期限，毫秒，必须大于 0 |
| `SEEFOOD_ARTIFACT_URL_TTL_MS` | `900000` | 下载地址期限，毫秒，且不晚于上下文到期 |
| `SEEFOOD_SAVED_CONTEXT_RETENTION_MS` | 未启用 | 完整保存且无活动依赖后的提前清理等待时间，毫秒；可为 0 |

当前开发会话有效期 1 小时，上传凭证有效期 15 分钟。单批最多 9 张图片，单张最多 20 MiB；后端完整解码上限为 1 亿像素，JSON 正文上限 1 MiB。这些是联调限制，正式限制需结合设备和远程资源重新验证。

## 固定生成场景

| `SEEFOOD_MOCK_SCENARIO` | 观察内容 |
| --- | --- |
| 不设置、`menu` 或 `complete` | 正常菜单、聊天、译图和文字翻译 |
| `unknown-price` | 价格无法确认的菜品 |
| `no-cards` | 未取得菜品卡片；后续操作保留图片输入 |
| `failure` | 菜品生成与独立文字翻译失败 |
| `translation-failure` | 译图失败，菜品卡仍可完成 |
| `chat-failure` | 聊天失败 |
| `chat-partial-failure` | 首次尝试先有片段后失败；显式重试完整替换同一回复 |
| `dietary-conflict` | 固定含蛋例与蛋过敏／纯素限制明确冲突 |
| `dietary-failure` | 独立偏好检查失败 |
| `text-failure` | 双向交流和卡片草稿的文字翻译失败 |

菜品实物模式呈现身份不确定的固定解释；中文目标菜单和实物照片返回无须译图。场景开关只影响新执行的固定生成，已完成任务不会因修改配置而重新生成。失败任务的显式重试仍使用原冻结输入。

例如观察卡片先完成、译图后完成：

```sh
SEEFOOD_TRANSLATION_DELAY_MS=10000 npm run server:dev
```

例如观察部分回复、离开后恢复及同一回复重试：

```sh
SEEFOOD_MOCK_SCENARIO=chat-partial-failure SEEFOOD_CHAT_PARTIAL_DELAY_MS=6000 npm run server:dev
```

保存失败、离线、响应丢失、旧响应延迟和删除竞态由测试中的平台存储、文件、网络或时钟边界控制，业务 HTTP 接口没有任意状态注入字段。场景与 D 用例关系见[模拟材料](mocks/README.md)。
