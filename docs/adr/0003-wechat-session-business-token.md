# 微信登录凭证换取业务访问令牌

状态：已接受，2026-10-06；真实平台接入待验证。讨论来源为 Q21，见[讨论索引](../archive/2026-10-06-discussion.md)。

核心流程无需用户操作登录页面，但后端仍需确认临时图片、上下文与任务的所有者。正式环境由后端验证微信登录凭证，再签发短期业务访问令牌；AppSecret 与微信会话密钥保留在后端。

## 取舍与后果

沿用微信身份体系满足首版小程序的身份来源需求，无需增加账号密码注册流程。业务令牌用于访问本产品接口，上下文、图片、任务与清理记录均按已验证的所有者隔离，客户端自报的用户标识或记录 ID 不作为访问凭证。

代价是后端需要实现登录凭证验证、业务令牌签发与过期处理，并在每类资源访问中校验所有者。该选择依赖微信登录配置，方案接受不代表真实调用已经验证。

## 联调边界与重新评估

本地使用单独启用的模拟身份入口，正式环境必须关闭。真实登录配置、令牌时效和过期行为在接入时验证，接口约定见[技术设计的身份规则](../technical/design.md#identity)。

身份识别沿用 [ADR 0001](0001-local-history-temporary-processing.md) 的保存边界，不引入云端历史或跨设备同步。若后续增加微信之外的客户端或独立账号体系，应重新评估身份来源与账号关联方式。
