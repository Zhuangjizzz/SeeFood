# 本机保存完整历史，后端保留临时处理材料

状态：已接受，2026-10-06。讨论来源为 Q19 及 Q3、Q6、Q16–Q18，见[讨论索引](../archive/2026-10-06-discussion.md)。产品依据为 [PRD F9](../product/prd.md#f9-本机历史与设置)。

用户需要离线回看已保存内容，也需要退出小程序后处理继续、重进时取得结果；首版不承诺跨设备恢复。因此，完整历史、偏好和个人沟通卡以本机保存为准，后端仅保留处理与恢复必需的任务、输入和结果，到期清理。

## 取舍与后果

长期云端历史可为跨设备恢复提供基础，但会引入当前范围之外的同步与双端冲突处理。本方案将长期历史责任留在客户端，同时用后端临时材料承接退出后的处理与结果交付。

- 客户端必须可靠保存文字和图片，并区分处理成功与本机保存成功；空间不足或写入失败需明确反馈。
- 后端材料过期后，旧历史仍可离线回看；发起新处理时可能需要用本机材料重建临时上下文。清除本机数据后不承诺恢复。
- 收藏沟通卡保存为独立内容，删除来源记录不连带删除收藏。处理与删除机制见[保存、恢复与删除机制](../technical/design.md#lifecycle)。

## 适用边界与重新评估

本决定不确定数据库、云平台或保留时长。具体期限、清理实现和第三方留存政策仍需在接入时落实，本机删除不等于第三方已删除。

若后续要求跨设备恢复、云端备份，或实测表明本机容量无法支撑所需历史，应重新评估长期数据的保存责任。
