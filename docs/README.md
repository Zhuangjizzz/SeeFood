## 文档维护

- 产品范围和核心要求由 PRD 定义，具体行为由功能规格细化；修改范围时更新 PRD，修改操作或异常时更新对应功能章节及验收用例。
- 页面设计说明行为的呈现方式，技术设计说明实现机制。引用功能规则，避免另行维护相同规则的完整副本。
- OpenAPI 是 HTTP 结构的唯一定义；技术设计补充结构无法表达的关联、版本和时间约束。契约变化同步检查模拟样例与关联用例。
- ADR 保留重要取舍的原因和后果，术语放在 GLOSSARY，调研依据放在研究目录。已接受方案、待实现内容和已执行验证分别标记。
- F／A／R／D 编号保持稳定，已撤销编号留在修订记录。历史讨论留在归档，通过链接追溯，不按问答顺序组织现行规则。

## 开发前与完成检查

每个批次先明确对应需求和验收编号，读完相关功能章节；关键页面具备可核对的布局与状态，所需数据关联、接口和模拟样例明确后再实现。开发任务按需要记录在 GitHub Issues，工单引用主文档中的规则。

完成时执行对应 D 用例与模拟场景，保留运行条件和结果；界面按 AGENTS.md 的要求编译并检查模拟器。具体实施批次与发布前待落实事项见[技术设计的验证部分](technical/design.md#validation)。模拟通过不替代真实 AI、多语言质量或性能验收。
