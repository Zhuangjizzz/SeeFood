# 通用图片翻译迭代

状态：**语义验收尚未通过。** 用户明确要求通用代码，不针对三张样本局部修复。此前菜名词表已删除，旧通过日志标为已撤回。当前没有菜名映射或人工替换译文。

入口是 `translate_menu(image_path, target_language, image_translator, text_translator)`。[已确认的测试 seam](测试边界.md)。`translate.py` 接受任意可读取图片，当前针对中文菜单到英语、日语、韩语、西班牙语；中文目标返回原图。没有接入小程序。

## 当前流程

1. 有道图片翻译 Pro 提供 OCR 和坐标，通用重叠切片保护大图文字；逐行整理，未闭合括号连接软换行。
2. 向有道“大模型文本翻译 Pro”发送编号文字块和上下文，使用同一条餐饮提示词。内容完整性依赖返回的编号，价格通过 `<keep>` 原样保护。当前文本接口尚不可调用。
3. 验证编号、数量、受保护金额与单位；失败时明确保留原图和待核对状态。不会从自己的词表提供菜名译文。
4. 按坐标绘制模型译文。无法放入原区域时保留该区域原文并标为待核对，当前排版仍待改进；不声称复杂背景或任意版式已经可用。

## 实测与阻塞

三张真实菜单做了12次整图 Pro、36次长图切片 Pro调用，均成功。长图分段改善了 OCR，整图仍有漏字与价格识别错误。原始响应仅本地保留在 `fixtures/`，不提交用户图片。

2026-10-06 测试文本翻译：文档所述 JSON 请求收到 HTTP400；按官方 curl 示例改为表单后，收到 `code=110`，表示当前应用没有该服务权限。没有成功的上下文文本翻译响应；没有把离线测试的模拟译文当作真实改善成果。

需要在 [有道控制台](https://ai.youdao.com/console/#/app-overview) 为现有应用开通／绑定“大模型翻译 Pro”。用户已授权后续验证，开通后无需重复发送凭证。参考 [文本翻译文档](https://ai.youdao.com/DOCSIRMA/html/trans/api/dmxfy/index.html)。

## 运行与回归

Python 3.10+、Pillow。字体目前使用 macOS 系统字体，正式后端部署需配置可用字体。

```bash
python3 -m unittest discover -s docs/research/图片翻译/prototypes/youdao-menu-tdd -v
python3 docs/research/图片翻译/prototypes/youdao-menu-tdd/translate.py /absolute/path/menu.png --language en
# 成功生成三张图四语结果后，独立语义验收（当前预期失败，缺少成功证据）
python3 docs/research/图片翻译/prototypes/youdao-menu-tdd/acceptance_real.py
```

凭证运行时隐藏输入，也支持 `YOUDAO_APP_KEY` / `YOUDAO_APP_SECRET`。不把秘密放在命令行、源码或请求日志。真实请求和输出均在 Git 忽略目录；缓存键包含请求内容、语言、模型或提示词，改变请求不沿用旧响应。

当前7条通用回归测试通过：响应缺失编号、受保护价格改写、任意 API 译文、独立与行内价格像素、中文原图、缺失文本依赖、重叠切片原始坐标。测试 mock 仅位于外部 API seam。它们检查代码契约，**不能证明真实翻译语义正确**。`acceptance_real.py` 使用独立的关键译义检查；当前四语均因缺少成功的实时 API 证据而失败，记录在 `results/semantic-pending.log`。匹配关键概念仍不能替代完整人工审阅。

## 开通后的验收

固定三张真实菜单和四个目标语言，保存实际 API 请求、原始译文、译图和全部待核对项。人工从原图检查菜名食材/做法、物种、单位、分组与价格对应，允许自然译名差异；任何可读原文漏翻、错误物种或价格均不通过。根据错误类型调整通用的上下文、请求分块、API选项和渲染算法，禁止用样本词表使检查变绿。

再准备未经提示词调整的菜单作为保留验收集，才能判断是否推广到任意图片。现有样本不能证明全部图片都可正确处理。OCR本身错字时需要通用复核机制，目前尚未完成。
