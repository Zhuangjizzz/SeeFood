# 有道图片翻译首次实测

验证日期：2026-10-06（北京时间）。结论：**API 能直接生成译图；默认传统模型不能直接用于正式菜单，价格表达与长图分组需要处理。** 本轮是接口与合成样本验证，不是服务商最终选型或上线验收。

## 调用与响应

32 次已发起调用均收到 `errorCode="0"`：31 次 `render=1` 均得到可解码译图，1 次 `render=0` 得到文字响应且没有图片字段。没有重试。6 张合成图片均验证中文到英语、日语、韩语、西班牙语；另有首次英文重复、4 次英文切片及2次 Pro。样本内容不是真实餐厅照片。[原始请求记录](2026-10-06-smoke/requests.jsonl)

`render_image` 实测为不带 data URL 前缀的 Base64 JPEG。当前样本输出宽高等于输入：普通图 900×1200，长图 900×4800。`resRegions[].context/tranContent/boundingBox` 分别是原文、译文和 x,y,w,h；回填响应另有 `lines`。本轮 `image_size` 返回顺序是 `[高,宽]`，不能把它当 `[宽,高]`。`RequestId` 可用于向供应商定位请求；`AIGC` 字段也随响应保留。这些是本轮观察，不是完整接口契约。[首个完整响应（图片二进制另存）](2026-10-06-smoke/single-en-r1-d02c35b3.response.json)

这次成功证明当前凭证可调用图片翻译，未发生“未绑定实例”“签名错误”或“余额不足”；未登录控制台核查绑定配置和剩余额度。

## 时延与费用

环境：macOS 26.5.1 / arm64，Python 3.12.14，Pillow 12.3.0，本机当前网络，直接 HTTPS 到有道，串行、每次间隔至少 1.2 秒；没有小程序客户端、额外后端或 CloudBase。网络运营商、带宽及供应商内部地域未采集。普通输入 PNG 为约69–135 KB，长图约261 KB，四片约60–79 KB。

API 耗时包括本机上传表单、网络、供应商处理和读取完整响应，不能拆成 OCR、翻译、渲染的各自耗时；本机完成耗时包括图片解码与结果保存，但没有用户确认、手机上传、浏览器解码和显示。`render=0` 只有一次，且调用顺序与缓存状态不受控，不据此声称渲染额外需要固定时间。样本少、语言与输入混合，本轮不作 P95 性能承诺。

4 片英文串行 API 耗时累计 4.933 秒，本机预处理/解码/保存累计 5.028 秒；另有片间人为限速等待与最后合成，未采集完整全图墙钟时间。首片完成约1.426秒。分段的改善伴随4次调用，不能把单片时延当整图完成时延。[切片调用记录](2026-10-06-long-tiles/requests.jsonl)

刊例成本估算：30 次传统成功调用 ×0.04 元＋2 次 Pro ×0.05 元＝**1.30 元**。这是按当前首档单价估算，未核实实际扣款、体验金消耗或账户账单；没有新增购买资源包。[官方价格](https://ai.youdao.com/DOCSIRMA/html/trans/price/tpfy/index.html)

## 图片质量

- 普通单列、双列、几何插图、模拟截图、暗光斜拍合成输入：均能形成译图。观察到部分双列菜名被缩到较小字号，关键数字仍可找到；未用真实餐厅图片评估背景修复，也未统计完整人工翻译准确率。
- **价格表达不合格。** 单列传统英文把 `¥38` 写为 `Selections of 38`；西班牙语写为 `A 38`；日语写为 `38円です`，会误导人民币语义。韩语多数保留 `¥38`，但有 `68 ¥`。数字保留不等于价格保真。响应将独立价格区域识别为其他语言/未知，可能有关，但未验证根因。
- **长图整张处理不合格。** 32 道菜被聚为18个菜名文字区域；例如 `清蒸鲈鱼鱼香肉丝` 和四道菜名连成一组，译文出现跨行堆叠、小字号和价格错位。输出仍是900×4800，故不能从输出原尺寸反推内部没有缩放或图像质量合格。没有证据定位内部处理步骤。
- **已知行间分段改善排版。** 英文切片中32道菜恢复为32个独立菜名区域；对照节选的跨行合并消失。切点利用合成样本已知行间空隙，不是通用切片算法，未验证四种语言或任意菜单。价格误译仍存在。
- **Pro 不是通用修复。** 单列英文 Pro 保留8个 `¥` 价格并给出可读菜名；日语仍写成日元，且“夫妻肺片”仍有不恰当的字面译文。只执行两次，不据此推断 Pro 更快、完全正确或解决所有菜单问题。[Pro 响应](2026-10-06-model-pro/requests.jsonl)

图片和逐项观察见[对照记录](对照.md)，全部结果可用[离线查看文件](../demo.html)检查。

## 下一步

1. 使用真实菜单照片、电子截图、长截图，保留四种目标语言，并由能审阅对应语言的人检查。用户提供本地路径或附图即可；凭证无需重复提供。
2. 价格保护需要独立实现和验证：候选是检测价格区域后从原图恢复价格像素，或采用结构化响应自行标注。它是后续方案，当前原型没有实现；长图价格合并区域不能简单逐框恢复而忽略菜名对应关系。
3. 分段按实际菜单行/分组选择边界，保留坐标映射，评估整图、首屏、并发配额与费用。当前固定切点只用于对照。
4. 再与百度 V2.0 比较同一批菜单的价格表达、版式和端到端时间，决定继续采用有道回填、改用自绘或换服务商。

未验证：真实拍摄、食物照片纹理、完整语言质量、账户余额/精确费用、并发及 P95、小程序交互和端到端时间、原图/译图/日志留存与删除、任意长图上限。简体中文目标应直接展示原图，不新增调用。
