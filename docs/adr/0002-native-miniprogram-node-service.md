# 原生小程序与独立 Node.js 后端

状态：已接受，2026-10-06。讨论来源为 Q20，见[讨论索引](../archive/2026-10-06-discussion.md)。

现有前端为原生小程序，本轮需要在尚未选定云平台时完成本地联调，并让已接收任务独立于页面和连接继续执行。前端沿用 JavaScript／WXML／WXSS，后端采用独立 Node.js／TypeScript HTTP 服务；后端持久化任务后返回接收成功，由执行器完成处理。

## 取舍与后果

沿用原生前端保留现有工程基础，首版不承担跨端框架迁移。独立 HTTP 服务使任务执行与小程序页面、连接生命周期分离，也使本地业务验证可以先于云平台选择完成。

代价是项目需要自行实现任务恢复、身份验证与清理。页面通过稳定业务接口访问处理结果，当前固定模拟实现与后续真实 AI 实现共用该接口，避免页面依赖供应商返回结构。

## 本地方案与部署边界

已确认的本地联调方案使用 SQLite 保存临时任务与元数据、文件目录保存图片，用于验证进程重启后的任务恢复；模块与存储安排见[技术设计的模块与运行边界](../technical/design.md#architecture)。这些安排不自动构成云端多实例部署方案，发布前仍需落实持久化资源与执行器的运行方式。

若后续增加跨端交付，或部署验证表明任务执行与存储方式需要调整，应重新评估相关选择。本记录没有确定云平台，也不表示生产部署已经验证。
