# Local service

Run `npm ci`, then `npm run server:dev`. Node 26 or later is required. The service listens at `127.0.0.1:8787` and stores SQLite metadata and actual images outside the repository at `~/.seefood/development`. `SEEFOOD_DATA_DIR` selects another external directory; `HOST` and `PORT` select the listener. `PORT=0` chooses a free port and the first stdout line contains its URL.

The development identity route is enabled explicitly by `server:dev`; allowed identities default to `demo-owner-a,demo-owner-b`. The normal `server` script does not enable this route, and the launcher disables it in production. Real WeChat session verification remains outside this local implementation.

Upload a real image, confirm its asset, publish a new snapshot binding that asset, then submit independent `image_cards` and `image_translation` jobs to `POST /v1/jobs`. `GET /v1/jobs/{jobId}` returns persisted state and output. `GET /v1/contexts/{contextId}/jobs` restores task associations after a lost acceptance response. Follow its context-bound `nextCursor` until null; pages default to 50 tasks, with `SEEFOOD_JOB_PAGE_SIZE` selecting a smaller test bound (maximum 100). Exact request fields are in [OpenAPI](../docs/technical/openapi.json). Upload and completion do not create jobs. Job acceptance atomically stores its request, immutable snapshot, asset references and request-idempotency response before returning 202. Independent jobs execute concurrently within one process, outside HTTP requests, and resume queued/interrupted work from SQLite after a process restart. This is a single-process local service, not a distributed queue.

Only generation is simulated. `SEEFOOD_MOCK_SCENARIO` accepts `menu` (default), `unknown-price`, `no-cards`, `failure`, `translation-failure`, or `chat-failure`. Dish-mode image requests produce uncertain dish identity. The fixed texts exist in all five supported languages; identifiers and snapshot versions always come from the actual accepted job. `SEEFOOD_TRANSLATION_DELAY_MS` delays the mock image translator for staged observation. `SEEFOOD_WORKER_DELAY_MS` controls the executor interval for bounded local restart tests. These options are runtime configuration, never HTTP request fields.


`server/jobs.ts` owns common persistence and execution. Add a `JobHandler` through `createService({jobHandlers})` to extend a stage: validate cross-object input in `prepare`, invoke the generation boundary in `generate`, and validate output relationships in `validateOutput`. Input preparation executes in the same database transaction as acceptance. The executor verifies real asset bytes and current task attempt/revision before publishing. `server/contract.ts` owns structural validation and common errors.

Translation output is a real PNG stored outside the project. Its dynamic download URL requires the owner’s business token; the client uses `wx.downloadFile`, checks image dimensions, and copies the bytes to its persistent `USER_DATA_PATH`. Original and translated images have independent file paths and saving states. Chinese-target menus and dish photos return `not_required` without generating a duplicate image. Job retrieval refreshes the current service URL without changing the business revision.

Client recovery in `core/recovery.js` matches exact saved request kind, target and frozen version, then calls the consumer’s guarded application. Image recovery restores both stages and their files, without creating or retrying generation. Completed tasks with unsaved structure remain eligible.

The result reader persists each image’s original/translation choice. First viewing resolves the available default once; later completion only updates availability. Failed or interrupted image saving can be retried without generating again. Custom fullscreen, stage retries, dietary review, save acknowledgements, deletion and terminal expiry are implemented in their dedicated modules. No cloud deployment, real AI response quality, physical-device file limits or production identity guarantee is implied by local tests.

Record chat uses the same `POST /v1/jobs` and query endpoints with `kind=chat`. Each record permits one active message pair. The client freezes every image, saved card, completed message pair and saved preferences into a new snapshot, excluding the current question/reply. Known card/message identities remain bound to their original owner and record. Chat outputs include fixed explanation, recommendation, two-portion reference-price and communication-card examples. Unknown prices remain unknown; communication attachments retain their full text and original language. The native result page opens `/pages/chat/chat`; completed messages are stored locally and remain readable offline.

`core/record-context.js` serializes snapshot writers per record. Upload and chat share one instance: acquire `contexts.run(recordId, operation)`, replay `publishPending(recordId)` before allocating a new version, persist the exact new snapshot/request before HTTP, and release the queue before long polling. `core/chat.js` exposes send, localized quick questions, guarded apply/recovery and save retry. A late initial POST cannot overwrite a newer recovered reply.



Run `npm test` for public client operations, actual HTTP/process/SQLite/file behavior and native page adapters. Run `npm run typecheck` separately. Shared WeChat simulator compilation and layout checks are coordinated in the integrated checkout.

Temporary retention uses `SEEFOOD_CONTEXT_RETENTION_MS` (default 86400000 ms for newly created contexts). Existing contexts retain their persisted deadline. At expiry the service fences writes, returns expired job metadata, and removes original/translated files plus snapshot, frozen input, result and idempotency bodies. The owner-bound expiry identity survives restart and cannot be reused. File cleanup retries from its durable lifecycle state. Local history has no corresponding expiry.

`SEEFOOD_ARTIFACT_URL_TTL_MS` (default 900000 ms) controls signed download URLs, capped by the context deadline. A URL still requires its owner's business token; an expired URL returns `DOWNLOAD_EXPIRED`. GET the same job to obtain a fresh URL without changing its content revision, attempt or saved-file identity.

Optional `SEEFOOD_SAVED_CONTEXT_RETENTION_MS` enables early collection after its grace period. It is disabled when unset. Collection requires every current succeeded result and translated artifact to be durably acknowledged through `POST /v1/jobs/{jobId}/ack`; active jobs, retryable failures, incomplete uploads and newly prepared unconsumed snapshots retain the context. These development values are not production retention commitments. Controlled tests use `createService({now})` and `service.retention.sweep()` without any HTTP state-injection endpoint.

The client rebuilds expired contexts only for explicit new submissions, retries or appends. Existing saved dish text allows text-only record-chat rebuilding; unavailable required originals lead to the localized add-photo route. It retains the record and completed message/card identities, local images and former context IDs for eventual deletion. Independent exchange/card drafts also keep their local content while explicit new translations create a fresh temporary context.
