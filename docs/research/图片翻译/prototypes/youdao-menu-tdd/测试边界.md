# 真实图片翻译的测试边界

2026-10-06，用户已确认覆盖英语、日语、韩语、西班牙语，随后明确要求对任意图片采用通用处理，禁止为三张样例局部修复。

公开接口仍是 `translate_menu(image_path, target_language, image_translator, text_translator)`：图片及目标语言输入，译图、逐条原文/译文/坐标和待核对事项输出。`image_translator.translate(bytes, language)` 与 `text_translator.translate(text, language)` 都在供应商 API seam；真实调用与记录回放是不同 adapter。新增文本依赖沿用用户确认的图片到输出 seam，不测试私有函数。

代码只负责通用的分段、OCR 行分离、坐标映射、上下文请求、价格保护、响应完整性与渲染，不含菜名词表、文件名分支、样例固定坐标、人工替换译文。语义改善必须由真实 API 产生。测试预期来自独立人工读图，使用允许的译义或关键概念，不用逐字相等证明语义。

三张菜单是验收数据，不是实现的数据源。响应回放按请求内容、语言和提示词哈希严格匹配；提示词变更不能继续回放旧结果。价格与单位保持原文字符，供应商修改时拒绝将该组冒充完成。中文目标直接返回原图。

此前按样例词表得到的日志在 `results/abandoned-local-fixes/`，已明确撤回。后续从新的红测试开始，按一个行为失败 → 通用修正 → 通过执行迭代。
