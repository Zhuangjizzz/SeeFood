# SeeFood 产品需求文档

- 版本：v1.7
- 更新日期：2026-10-06
- 状态：首版产品需求基线，范围与核心行为已确认；真实接口效果、性能阈值及输入限制待验证。
- 交付形态：微信小程序，由产品负责人和 AI 开发助手共同完成，目前不预设截止时间。

本文定义产品价值、首版范围与整体成功标准。具体操作和异常行为见[功能与交互规格](functional-spec.md)，实现方案见[技术设计](../technical/design.md)，布局与视觉见[页面设计](../design/README.md)。本轮使用模拟 AI 的交付边界见[功能规格第 1 节](functional-spec.md#1-本轮交付与范围)，真实 AI 要求保留并在后续接入后单独验收。

## 1. 背景与产品价值

外国游客在中国餐厅需要理解中文菜单、菜品实际内容、食材和口味，并判断是否符合个人饮食要求。菜名直译往往不足以支持选择，例如“夫妻肺片”“蚂蚁上树”需要结合菜品解释。

SeeFood 面向已经入座的游客，帮助其理解菜单、选择菜品、与店员沟通，并在用餐中理解眼前的食物、常见吃法和相关文化。产品需清楚区分可确认的信息、常见菜谱知识和需要向店员核实的事项。

## 2. 目标用户与使用场景

### 2.1 目标用户

以受支持语言交流、看不懂中文菜单、对中国菜不熟悉的来华游客。首版围绕当前用户的个人饮食需求提供帮助。

首版完整支持英语、日语、韩语、西班牙语和简体中文，覆盖界面、识别结果、AI 对话与沟通卡，使用户可用任一语言完成核心流程；简体中文也用于现场演示。原始中文菜名保留供核对与沟通，语言切换规则见 F1。

### 2.2 核心场景

| 场景 | 输入与期望结果 |
| --- | --- |
| 看纸质菜单 | 拍摄菜单，必要时多张补拍，理解菜品并核对原菜单 |
| 看电子菜单 | 导入点餐小程序截图或长截图，获得与拍照菜单相同的识别和解释能力 |
| 挑选菜品 | 点击快捷建议或输入需求，结合当前菜单与个人偏好获得候选菜及原因 |
| 了解参考价格 | 在对话中说明菜品和数量，按可确认的菜单价格算价，保留未知项 |
| 与店员沟通 | 展示预置／自定义沟通卡，或通过双向文字翻译交流 |
| 理解上桌菜品 | 拍摄菜品并提问，了解可辨认的食物、常见吃法与饮食文化 |

## 3. 首版范围与后续规划

### 3.1 首版范围

- 拍照、相册、多图和长截图输入；菜单识别、原图／译图切换与自动生成的结构化菜品卡片。
- 实际菜品照片识别、解释与吃法说明。
- 五种语言、个人饮食偏好、围绕菜单和饮食文化的 AI 对话、快捷建议、按需推荐与对话算价。
- 可自定义、增删、编辑、分类和换色的个人沟通卡库，以及店员沟通中的双向文字翻译。
- 本机保存偏好、沟通卡与完整历史，支持删除、清空和已保存内容的离线回看。
- 融入菜品解释的简短中国菜知识；图片翻译质量、处理速度和对话延迟的调研与优化。

菜单版式与规格差异较大，首版聚焦理解和沟通，取消界面内选菜、数量编辑、购物车与独立点餐清单。菜品卡片用于浏览，推荐与算价通过对话完成。

首版不提供识别菜名编辑或保存接口。用户可核对原图、补拍、追加图片或在对话中补充；对话补充不直接改写识别结果。

### 3.2 后续规划

- 经资料积累与核验的独立中国菜小课堂、更丰富的教学图片和动画。
- 附近提供某道菜的餐厅推荐。
- 多人饮食偏好合并、整桌搭配与人均预算优化的专门流程。
- 餐厅系统下单、在线支付、结账、跨设备同步与付费功能。
- 语音输入、朗读与实时语音翻译。

首版对话允许用户补充人数、预算或搭配需求，但不为此建设专门的多人资料和预算优化流程。

## 4. 主流程与页面职责

### 4.1 首次使用

系统语言匹配时直接进入拍照首页并提供页内引导，未匹配时先选择受支持语言。偏好可设置或跳过，无需操作登录页面即可开始。语言入口与切换规则见[功能规格第 2 节](functional-spec.md#2-首次使用导航与语言)。

### 4.2 拍照页与已有识别结果

主入口提交图片创建新记录，已有结果页追加照片补充原记录；不同记录的菜单与对话独立，用户无需预先建立“本次用餐”。最近记录与历史可回到原结果。输入与预览见[功能规格第 3 节](functional-spec.md#3-图片输入与提交)，退出后的处理恢复见[8.3 节](functional-spec.md#83-离开页面与退出恢复)。

### 4.3 识别结果与按需聊天

同次菜单识别自动提供图片视图与卡片，用户先浏览可用结果，按需进入当前记录的对话获取解释、推荐、算价或沟通帮助。具体行为见[结果浏览](functional-spec.md#4-结果浏览与菜品详情)与[对话发送](functional-spec.md#51-进入发送与结果)。

### 4.4 页面职责

首版包含拍照、结果浏览、菜品详情、独立对话、个人沟通卡、历史及偏好／语言设置。导航和页面分区集中在[页面设计](../design/README.md)，每项操作及异常状态集中在功能规格对应章节。

## 5. 功能需求

### F1. 全流程多语种

- 五种语言覆盖界面、译图、菜品内容、聊天和沟通卡，保留原始中文菜名供直接查看。
- 界面语言切换使用内置静态文案；已有译图、解释、聊天、推荐、算价回复和自定义／AI 卡片保留原内容与语言，不触发翻译、重生成或清空。
- 沟通卡显示中文与该卡片语言的对照，中文卡片避免重复相同文字。预置卡片与已编辑内容的切换边界见 F8。
- 五语言切换及静态界面与旧动态内容共同展示均纳入视觉验收，关键文字完整、清晰，不截断或遮挡。

### F2. 图片输入与菜单识别

- 相机和相册均为正式输入方式，拍摄／导入前选择菜单或菜品模式，默认菜单，追加时同样可选。
- 支持纸质菜单照片、普通电子菜单截图、点餐小程序长截图和多张补充图片。菜单相册多选后可预览、移除、排序，再统一提交，新建或追加按入口决定。
- 长截图覆盖上传、处理、图片缩放和卡片浏览全流程；优先验收清晰印刷菜单与文字清晰的电子截图。
- 识别可见菜名、价格及对应关系，未知价格明确保留；不依据菜品知识生成价格，电子菜单的导航、购物车、促销等内容不作为菜品推荐。
- 重复图片、重复菜名、套餐和规格差异通过样本验证明确处理范围，避免错误合并菜品与价格。用户可核对原图或补图，不提供菜名编辑。

### F3. 菜单译图与菜品解释

- 同次菜单识别保留原图、生成目标语言译图和结构化卡片，用户无需进入聊天或点击推荐。三者关联同一菜单，菜名、价格和来源对应，可回原图核对。
- 译图保留原菜单的分组、图片、价格与版式关系，质量要求见第 6 节；原图与译图均支持缩放，长图可浏览。
- 目标语言为简体中文时保留中文图片并生成解释卡片；实际菜品照片没有可翻译文字时提供原图与解释，无须重复译图。
- 卡片展示中文菜名、生成时目标语言的菜名、识别价格和一句话解释；详情补充主要食材、口味、常见做法、饮食提示、吃法、文化与待确认事项。
- 常见菜谱知识与本店实际配料明确区分，推断使用“常见做法”“可能包含”等表述。实际菜品优先引导拍摄一道菜，不确定时允许补充说明或清晰图片，不强行匹配菜单菜品。

### F4. 饮食偏好与判断边界

| 信息类别 | 用途 |
| --- | --- |
| 过敏信息 | 记录具体过敏原与补充文字，识别已知／可能冲突并生成针对性询问 |
| 饮食限制 | 记录素食、不吃猪肉、不摄入酒精等限制，单独记录宗教饮食要求，影响候选范围 |
| 口味偏好 | 记录辣度、清淡、甜口、不喜欢的食材等，影响排序与解释 |

- 偏好可跳过、保存、修改，各类允许文字补充。具体过敏原和宗教饮食选项需核验，简短标签不等于完整配料或制作条件说明。
- 明确冲突项不进入推荐，但保留菜单浏览与原因；可能冲突或信息不足时显示原因，并提供向店员询问的入口。待确认事项贯穿详情与后续对话。
- 未识别到过敏原不等于“可以放心吃”，菜名、照片和常见菜谱不能证明餐厅的宗教饮食资质或制作条件。
- 跳过偏好时可使用核心流程，通用推荐说明尚未结合个人限制。修改后重查提示，等待与失败可辨认；旧对话保留原文，旧推荐标记需重新确认，后续推荐使用新偏好。

### F5. AI 对话与快捷建议

- 支持五语言文字对话，围绕当前记录解释菜品、吃法、食材、文化与餐桌习惯，并提供推荐、参考算价和店员沟通帮助。
- 菜单、照片与对话在记录内关联，不混入其他记录的餐厅菜品；语言、偏好和已收藏卡片可持续使用。
- 快捷建议随菜单／菜品照片场景变化，使用自然语言，点击发送行为见[功能规格 5.1](functional-spec.md#51-进入发送与结果)。
- 已发消息在离开或退出后继续处理，重进可恢复状态；未发送草稿与阅读位置按记录在本机保存，草稿不自动发送，新回复不打断旧内容阅读。回复中断保留片段并标未完成，重试成功替换对应回复，不重复问题或拼接两次回答。
- 本轮使用模拟回复。真实回复、追问策略、新请求语言和 Prompt 后续确定，上下文组织与模型选择结合调研落实。

### F6. 按需推荐

用户点击快捷建议或明确提问后，默认结合当前菜单和偏好给出 3–5 道候选菜，每道包含原因、已知限制与待确认事项，可进入详情或继续追问。候选不足时展示实际数量并说明原因；无合适候选时提示补充菜单或需求，不生成当前菜单中不存在的菜品凑数。用户可继续调整口味要求，或补充人数、预算和搭配需求。

### F8. 沟通卡与双向文字翻译

- 独立个人卡片库提供可调整的预置卡片，支持标题、分类、颜色、编辑、删除与排序；分类和颜色辅助查找，保留可读的标题与文字。
- 用户输入定制内容，生成中文对照后可检查、编辑并保存；AI 对话生成的询问卡可一键收藏。涉及具体菜品时保留中文菜名，复用时可辨认询问对象。
- 向店员展示时放大中文并保留卡片语言对照。预置多语言文案随界面切换；已编辑、自定义及 AI 生成的保存内容保留原语言。
- 游客和店员均可输入文字并获得双向翻译；语音能力留待后续。

### F9. 本机历史与设置

- 本机持续保存语言、偏好、个人沟通卡及完整历史，图片自动保存离线副本；保存中、成功和失败可辨认，历史默认不过期。
- 沟通卡草稿、卡库浏览状态与当前文字交流可在退出后恢复；当前文字交流只保留双方最近内容及未发送草稿，主动清空后重置，不增加过去交流的历史列表。
- 已保存的菜单文字、原图与译图、菜品解释、对话和沟通卡可离线回看，包含推荐与算价回复；未保存图片明确提示，新生成内容需联网。
- 支持单条删除和清空。删除移除记录及关联内容，已收藏沟通卡作为完整独立副本保留；处理中记录也可删除，停止可停止的后续工作，迟到结果不能恢复记录。
- 空间不足提示用户选择清理，不静默删除其他历史，不把保存失败标为成功；首版不承诺跨设备恢复。
- 核心流程无需显式登录。本产品后端只保留处理与退出恢复必需的临时任务、输入和结果，到期清理，不建设长期历史同步。外发数据、具体期限与删除机制在接入方案中明确，第三方留存政策另行核实，本机保存不代表外部服务没有接收或留存数据。

### F10. 中国菜知识内容

首版将简短知识融入眼前菜品的详情与对话，可用文字和图片解释相似食物的区别、食材与常见吃法。同时积累菜名、做法、地域差异和图片资料；独立小课堂需整理来源并核验内容，当前生成解释不自动作为已审核课程。

### F11. 对话算价

用户在当前记录对话中说明菜品、数量或规格，系统按可对应的菜品、数量及可确认菜单价格计算参考金额，保留中文菜名与价格对应关系，结果留在对话中。未知价格保持未知；歧义、追问及部分报价策略后续在 Prompt 文档确定。本轮用固定回复验证展示与保存，不维护独立选菜或订单状态，不连接餐厅下单、支付和结账。

## 6. 非功能需求：展示质量与响应速度

### 6.1 翻译展示质量

- 菜名、价格、解释、卡片与来源图片的对应清楚，长截图可放大核对。
- 五语言关键内容完整可读，静态界面切换及与旧动态内容混合展示时没有遮挡、重叠和文字丢失。
- 译图尽量保留分组、图片和版式关联，换行、字号和文本区域适应目标语言，不遮挡关键价格或造成跨菜品错位，并保留原图核对入口。
- 可用内容分阶段展示，具体布局与视觉规则见[页面设计](../design/README.md)。

### 6.2 速度指标

| 指标 | 计时口径 | 记录要求 |
| --- | --- | --- |
| 图片首次可读结果耗时 | 确认提交到出现第一批可读的本地化菜品结果，包含必要上传时间 | 中位数、较慢请求表现及失败率 |
| 图片基础结果完成耗时 | 发起处理到基础识别与翻译完成 | 按普通照片、长截图、多图分别统计 |
| 译图可查看耗时 | 发起处理到可查看译图 | 记录识别、翻译和视觉渲染各阶段关系 |
| 对话首段有效回复耗时 | 点击发送或建议到首段有意义回复，加载提示不计入 | 中位数和 P95 |
| 对话完整回复耗时 | 发起问题到完整回答可用 | 结合回复、菜单及上下文长度统计 |
| 端到端失败率 | 已发起的图片或消息中未得到可用结果的比例 | 区分上传、识别、翻译、模型与展示失败 |

数值目标待接口调研和实测确定。正式验收前补齐阈值、设备、网络、输入规模及测量方法，不将模拟耗时视为实际性能。

### 6.3 等待与失败体验

操作后显示明确反馈，多图与长图分阶段展示可用结果，对话逐步展示方式随真实接口验证。失败保留输入和成功内容，提供针对失败图片／阶段的重试或补拍；未上传材料重进可找到，联网后由用户手动重试。不完整内容标明状态，未知字段保持明确。

## 7. 调研任务

| 编号 | 主题 | 必须形成的结果 |
| --- | --- | --- |
| R1 | 图片识别与翻译，有道 API 为候选之一 | 核实五语言、菜单照片和长截图支持、输入限制、输出、耗时及费用 |
| R2 | 菜单结构还原 | 验证菜名价格对应、多列、长图、重复项、套餐与规格，明确不确定性及补图处理，不建设菜名编辑 |
| R3 | 翻译展示质量 | 提供多语言卡片与译图样例，核验排版、对应关系、可读性和速度；简体中文检查原图与解释卡片 |
| R4 | AI 对话 | 比较解释、推荐约束、菜品问答、多语质量、上下文与首段延迟；验证菜品、规格、数量、价格对应及计算正确性 |
| R5 | 性能优化 | 建立基线，定位各阶段耗时，评估压缩、分段、缓存与流式输出 |
| R6 | 数据与成本 | 明确外发数据、保存期限、删除边界、调用成本和图片／次数限制 |
| R7 | 内容与评估样本 | 准备有来源的菜单、菜品及饮食知识样本，核验多语解释并为小课堂积累数据 |

资料与实测见[技术调研](../research/README.md)，技术选择由实现方案承接。上述真实 AI 调研与验证在后续接入阶段完成。

## 8. 首版验收场景

以下为计划中的验收项，不代表已经实现或通过测试。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 五种语言分别完整使用 | 每种语言都能完成设置、导入菜单、查看解释、提问、获取推荐与算价、沟通和查看历史 |
| A2 | 导入电子菜单长截图 | 可以完成导入、处理、原图／译图切换及缩放、自动生成卡片并浏览，菜名与可识别价格保持对应 |
| A3 | 追加菜单或菜品照片 | 先从拍照页进入已有结果，再追加图片；已有内容和上下文保留 |
| A4 | 理解不适合直译的菜名 | 给出通俗的菜品解释，不仅输出菜名的字面翻译；推断的配料不写成本店已确认配料 |
| A5 | 点击快捷推荐 | 聊天中显示自动发送的当前语言提问；从当前菜单给出候选菜及理由，不生成不存在的菜品 |
| A6 | 设置饮食限制 | 明确冲突项不进入推荐；可能冲突和未知信息保留提示及询问入口 |
| A7 | 未设置个人偏好 | 可以使用核心流程；通用推荐说明尚未结合个人饮食限制 |
| A8 | 用餐中拍菜追问 | 可以查看菜品照片与解释，继续询问食材和吃法；识别不确定时能补充信息或图片 |
| A9 | 自定义与收藏沟通卡 | 可创建、编辑、分类、换色、删除和调整卡片顺序；AI 生成卡片可收藏；界面语言切换后，已保存的自定义／AI 卡片仍展示原有内容，不自动重译 |
| A10 | 与店员文字沟通 | 中文和用户语言均可输入，并得到对应翻译 |
| A12 | 本机历史管理 | 重新进入可读取保存内容，并能单条删除和清空 |
| A13 | 图片处理或聊天失败 | 保留输入及成功结果，给出可执行的重试或补拍入口，不展示编造的补全结果 |
| A14 | 视觉和性能验收 | 完成第 6 节的视觉检查；在补齐测量条件与阈值后，使用实际接口数据验证速度 |
| A15 | 从拍照页再次直接拍摄或导入 | 新建记录，旧记录可从历史重新打开；新旧菜单与对话互不混入 |
| A16 | 译图与卡片作为基础输出 | 同次菜单识别提供译图和自动生成的卡片，无需进入聊天；切换原图／译图不清空卡片，内容与本次生成目标语言对应；之后切换界面语言不改变既有输出 |
| A17 | 在对话中按菜单算价 | 本轮以固定模拟回复验证算价消息的展示与保存；实际 AI 接入后，在菜品、规格、数量与价格明确的样例中核验金额及来源，缺失价格不被编造；歧义与部分报价的回复策略随后续 Prompt 文档确定 |
| A18 | 处理中离开结果页 | 图片已上传并开始处理后，转到其他页面不会停止处理；可找到该记录，返回时显示当时进度或结果 |
| A19 | 离线回看已保存内容 | 断网后可回看已成功保存的文字、原图与译图、对话和沟通卡；未保存完成的图片明确提示，需要生成新内容的操作不伪装为成功 |
| A20 | 修改偏好后的内容更新 | 相关菜品提示重新检查且等待／失败状态可见；旧对话保留原文，旧推荐标记需重新确认，后续推荐使用新偏好 |
| A21 | 退出后恢复处理中的记录 | 图片已上传并开始处理后退出小程序，处理继续；重新进入恢复原记录状态，完成时可看结果，失败时可重试，重新进入不重复创建记录或处理请求 |
| A22 | 切换静态界面语言 | 五种语言下导航、按钮、标题、表单与状态提示布局清晰美观；既有译图、解释、聊天和自定义／AI 卡片内容不变，切换动作不发起 AI 翻译或重生成请求 |
| A23 | 主导航与记录入口 | 底部提供拍照、沟通卡、我的三个入口；我的可进入历史、语言设置和偏好；最近记录与历史能进入对应结果，记录不混淆 |
| A24 | 结果浏览与聊天往返 | 结果页上方图片预览、下方菜品卡片，添加照片和固定的“问 AI”入口可用；聊天属于当前记录，返回后继续浏览同一记录；部分可用内容无需等待全部处理完成 |
| A25 | 拍照页默认入口 | 进入拍照页先看到拍摄、相册导入和最近记录；点击拍摄才打开相机，可先确认语言或直接导入截图 |
| A26 | 多图与长图浏览 | 缩略图切换当前图片及其关联卡片；切换不删除其他卡片，聊天范围仍是该记录全部相关菜单与图片；图片可全屏缩放，长图可滚动 |
| A27 | 菜单／菜品模式 | 拍摄和导入前可选择菜单或菜品，默认菜单；追加时同样可选，记录归属保持正确 |
| A28 | 多图提交前预览 | 多选后可预览、移除和排序；统一提交后图片顺序和记录归属正确；提交前退出不发起处理 |
| A29 | 分项失败与待上传恢复 | 某图或阶段失败不清空成功结果；重试定位失败项；未上传材料在重新进入后仍可找到，联网不自动提交 |
| A30 | 自动保存与空间不足 | 内容持续保存，图片自动保存供离线查看；保存状态真实，空间不足时提示清理，不静默删除旧历史 |
| A31 | 删除与独立收藏 | 删除记录后关联内容消失，已收藏沟通卡仍完整可用；处理中的记录删除后不会被迟到结果恢复 |
| A32 | 聊天恢复与重试 | 离开或退出后已发消息继续处理；中断回复标未完成，重试成功替换对应回复，不重复问题或拼接两次回答，草稿不自动发送 |
| A33 | 无菜名编辑入口 | 结果和详情提供查看、补图与聊天入口，不提供识别菜名编辑或保存动作；沟通卡编辑与偏好修改正常可用 |

## 9. 首次开放与产品验证

- 首版向一批真实来华游客开放免费测试，同时用于比赛展示。
- 优先观察用户能否独立完成点餐和用餐流程，菜品解释是否看得懂，以及店员是否能理解沟通内容。
- 分别记录长截图处理、五种语言使用、推荐与算价后的继续追问、补充图片和沟通卡使用中遇到的问题。
- 图片大小、调用次数及费用控制，在接口调研后确定；此版本不承诺无限使用。
- 产品效果指标和性能指标分开评价，既检查回答是否有用，也测量等待时间。
